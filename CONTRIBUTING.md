# Contributing

Describe the intended behavior and include a small reproduction or scenario. For changes to a public API, include the affected APIs, compatibility impact, and migration guidance. The [development guide](docs/en/development.md) explains how those decisions fit into the OpenSpec workflow.

Keep comments, documentation, diagnostics, and test fixtures in English. Preserve the exact copyright and license notices in adapted files. Provide the upstream path and revision for any new adaptation. See the [third-party notices](backend/THIRD_PARTY_NOTICES.md) for examples.

The [user guide](docs/en/user-guide.md#checks) lists the checks the maintainers run on Linux. The [CI workflow](.github/workflows/ci.yml) runs the same checks for every push to `main` and every pull request. The [versioning policy](VERSIONING.md) explains when an API change needs a new version.

Unless you explicitly state otherwise, any contribution intentionally submitted for inclusion in Crucible Core by you, as defined in the Apache-2.0 license, shall be dual licensed under the [MIT license](LICENSE-MIT) and the [Apache License 2.0](LICENSE-APACHE), without any additional terms or conditions.
